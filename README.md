# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：家属在线申请建床 → 家庭医生评估（病情、居住距离、照护人、医保资格、护理项目、风险等级）→ 审批建床 → 自动排班与上门路线 → 护士上门记录生命体征、压疮、换药、导尿、血糖血压、用药提醒、耗材领用、冷链温度与家属签字 → 医生远程复核并调整处方/复诊/转诊 → 耗材、冷链药品、护理收费、医保报销与自费项目进入**同一张账单** → 家属逐项确认、质疑、医保结算。任意争议都可按一张病床还原「申请—评估—计划—执行—照片—医嘱—签字—账单」全过程。

技术栈：Vue 3 + Vite + Element Plus（前端）｜ Spring Boot 3 + Spring Data JPA + Token 认证 + springdoc OpenAPI（后端）｜ PostgreSQL 15（数据库）｜ Docker Compose 一键启动。

## 一、一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后：

| 服务 | 地址 |
| --- | --- |
| 前端页面 | http://localhost:8088 |
| 后端 API | http://localhost:8080/api |
| Swagger UI | http://localhost:8080/swagger-ui.html |

首次启动自动建表并写入演示数据（5 名不同角色账号、患者、医保目录、完整业务链）。数据存于 Docker 卷 `homebed-pgdata`、`homebed-uploads`。

停止与清理：

```bash
docker compose down          # 停止
docker compose down -v       # 停止并删除数据卷（恢复全新演示数据）
```

## 二、本地开发启动

前置：JDK 17、Maven 3.8+、Node 20+、PostgreSQL 15。

1. 准备数据库：

```sql
CREATE USER homebed WITH PASSWORD 'homebed123' SUPERUSER;
CREATE DATABASE homebed OWNER homebed;
```

2. 启动后端（默认连 `localhost:5432/homebed`，可用环境变量覆盖）：

```bash
cd backend
mvn spring-boot:run
# 或自定义：DB_URL / DB_USER / DB_PASSWORD / UPLOAD_DIR
```

3. 启动前端（开发服务器自动把 /api、/uploads 代理到 8080）：

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173
```

前端生产构建：`npm run build`（产物在 `frontend/dist`，容器中由 nginx 托管并反代后端）。

## 四、演示数据与业务场景（已内置）

- 患者**张桂英**（脑梗康复+压疮，5.2km，高风险）：已建床 `JB0001`，今日护士上门完成压疮换药等服务，有现场照片、家属签字；发现渗液增多、低热 → 自动生成「病情恶化」风险事件，医生远程复核并下转诊/复诊医嘱；已出账，家属质疑「一次上门为何收 2 次换药费」，医保核对照片后承认超频次，**退还自付费 6 元**，家属确认后已结算。
- 患者**李德福**（糖尿病+留置尿管，9.6km，超出 8km 标准半径）：已建床，今日导尿护理+血糖监测，冷链胰岛素交接温度 9.5℃ → 自动生成**冷链异常**事件；空腹血糖 13.2 → 病情异常待医生复核；账单含一项**全自费敷贴**，家属已提出质疑（待处理）。
- 患者**孙玉珍**：建床后因**临时住院暂停**，未来计划自动挂起、住院期间不计费。
- 患者**吴桂兰**（15.3km、异地医保未核实）：医生评估**驳回**并说明原因。
- 排班中还演示了**家属不在家**、**耗材缺货（鼻饲固定贴库存 0）** 两类取消，均留痕且不计费不扣库存。
- 医保经办在服务后调整了「家庭病床巡诊费」价格（50→55 元、报销比例 80%→85%），账单按**服务当日快照**结算并标记「医保目录/价格已变化」。

## 五、建议验证路径（按角色）

1. **家属 `family`**：病床申请与进展 → 打开 `JB0001` 查看护理记录、照片、签字、医嘱与全过程时间线 → 账单与结算中确认/质疑费用。
2. **护士 `nurse1`**：排班与上门路线 → 查看每站「可解释安排」（负荷/半径/风险）→ 对未来计划「签到上门」，录入体征、护理、耗材数量（自动校验库存）、冷链温度，手写签字提交；可登记「家属不在家/缺货」未完成（不计费）。
3. **家庭医生 `doctor`**：对待评估申请完成六维评估 → 在建床生成周计划 → 远程复核与医嘱页处理待复核记录 → 暂停/恢复/撤床。
4. **管理 `admin`**：管理看板查看护士负荷、上门半径、耗材消耗、风险分布、结算概况 → 审批建床、人工改派护士 → 生成账单。
5. **医保经办 `yibao`**：医保合规审核（重复收费/超频次/目录变化/自费）→ 收费质疑处理（答复+退费）→ 维护医保目录与报销比例 → 对家属已确认账单执行结算。

关键接口亦可通过 Swagger UI（http://localhost:8080/swagger-ui.html）在线调试。
